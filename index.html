pstack

23 playbooks · 24 skills · 23 principles

Make a coding agent work like a careful engineer.

pstack is poteto's Cursor plugin for coding agents. You describe a task in your own words. /poteto-mode matches a playbook — a recipe for that kind of work — and runs the other skills as the steps fire.

Use it when the work has to be right: a bug you can reproduce, a change you can prove, a question you want cited, or a long run you can audit later. Skip it for one-line edits.

01

Start here

Three commands in a Cursor chat. You do not need to memorize playbooks first. Install, pick models, then give /poteto-mode one real task.

01

Install the plugin

In a Cursor chat, add pstack. Cursor confirms when it is installed.

/add-plugin pstack
02

Pick your models

Detects the models you have, asks for a reasoning budget, and writes ~/.cursor/rules/pstack-models.mdc. Start a new chat after it finishes so the rule applies.

/setup-pstack
03

Run one small, real task

Say the goal and how you will know it is done. Watch the todo list fill with the matched playbook's steps. This one is a Feature.

/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.

You do not name a playbook or list skills. A goal plus a checkable outcome is enough. /poteto-mode stays on for the chat until you opt out. Say new task when you change subjects.

Reach for itA defect, a feature you can verify, a cited question, or work you will leave running.
Type the goal“Repro first, then fix and verify” is a real constraint. The playbook honors it.
Don't list skillsA handwritten “use /how then /architect” usually reorders steps the playbook already sequences.
Name a skill to overrideReach for /how, /interrogate, or /bro when you want that move only.
02

How the pieces fit

Three layers, one habit. You talk in goals. pstack supplies the recipe, the moves, and the standing rules.

layer 1
Playbooks

A step-by-step recipe for one kind of task. /poteto-mode copies the matched playbook into the todo list before any work starts. There are twenty-three, including a fallback when none fit.

layer 2
Skills

Named moves such as /how, /architect, and /tdd. The playbook calls them as steps fire. Type one directly when you want that result without the full route.

layer 3
Principles

Twenty-three standing rules in five families. They bias every playbook toward small diffs and proof on the real artifact. You do not invoke them. You say their names to steer mid-task.

/poteto-mode → match a playbook → skills fire as steps → principles steer → a clean, verified reply

04

Playbooks

A playbook is a recipe for one kind of job. Filter by the work in front of you, then open a card for when it applies and what to type.

05

Skills

Skills are the individual moves. /poteto-mode runs most of them for you. Reach for one when you want that result only.

06

Principles

Twenty-three rules in five families. You do not invoke them. Say the name to redirect an agent mid-task, then expect it to name the decision the rule changed.

07

Models per role

pstack can use a different model for each role. Some roles run several models in parallel so reviews come from different angles. You only override the roles you care about.

Run /setup-pstack to detect your models and write the rule. A role with no line keeps the skill default. auto and inherit-parent mean “use the parent chat model,” not a model slug.
